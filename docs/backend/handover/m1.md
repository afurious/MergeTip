# M1 handover: Foundations

Branch `backend/m1-foundations`, branched from `main` at `04755b9`. Not pushed or merged.

## What works

- **`core`**: `TipState` with `as_str`/`FromStr`/`is_final`, plus an exhaustive test of every
  `(from, to)` pair against an independent allow-list. Also `Sats`/`Msats` with checked
  conversions and `2,100 sats` display, typed IDs, `ThreadRef`, `TipKind`, and the
  `Clock`/`SystemClock`/`FixedClock` clocks.
- **`crypto`**: `Keyring` envelope encryption (per-value AES-256-GCM key wrapped by `MASTER_KEY`,
  AAD-bound, rotation via `MASTER_KEY_PREVIOUS` + `rewrap`) and HKDF subkeys. `Redacted<T>` has no
  `Serialize` and zeroises on drop. The GitHub signature check is tested against GitHub's published
  vector. Tokens are random, base64url, and stored as SHA-256.
- **Schema** (`migrations/20261024143341_init.sql`, RFC 0001): users, installations,
  installation_repos, github_events, wallet_connections, tips, tip_events, bot_comments, jobs, and
  feature_flags (seeded with `payments_enabled = true`, `fiat_payouts = false`).
- **`store`**: repositories for users, installations, github_events and tips.
  `tips::transition` is the single writer of `tips.state`: compare-and-set, `version` bump and audit
  row in one transaction. A test fails if any other Rust file assigns `state`.
- **Job queue** (`store::jobs`): `SKIP LOCKED` claims with a 5-minute lease and a per-claim lease
  token (a reclaimed job can't be completed by its old owner). Also dedupe keys, `pg_notify` on
  commit, retry/backoff with jitter, dead-lettering, and `reschedule` for recurring jobs.
- **`runtime`** (new crate): typed env config, JSON/pretty tracing, pool and migrations, and a
  SIGTERM/Ctrl-C cancellation token.
- **`worker`**: `Runner` with N slots, LISTEN plus 1 s polling, panic isolation per job, a 30 s
  graceful drain, and a `noop` handler. Migrations run at startup.
- **`api`**: `/healthz` (plain `ok`, for Fly) and `/v1/health`. The JSON error contract covers
  404/405 fallbacks. Middleware: request ID, sensitive-header redaction, tracing, a 10 s timeout, a
  5 MiB body limit, and CORS limited to `PUBLIC_BASE_URL` with credentials. Graceful shutdown.
- **OpenAPI**: `mergetip-api openapi` prints the spec. `make openapi` writes
  `openapi/openapi.json` and regenerates the frontend client. A test fails if the committed spec is
  stale.

## How to run and demo

```sh
cp .env.example .env    # set MASTER_KEY=$(openssl rand -hex 32)
make up && make migrate
make dev-api            # curl localhost:8080/v1/health
make dev-worker
psql "$DATABASE_URL" -c "INSERT INTO jobs(kind,payload) VALUES ('noop','{\"hi\":1}'); NOTIFY jobs, 'noop';"
make check-backend
```

Both binaries were smoke-tested here: the worker ran a `noop` job via NOTIFY and drained on
SIGTERM, and the API served `/v1/health` and shut down cleanly.

## Deviations from the plan

- **`mergetip-runtime` crate added** (ADR 0002), so config, tracing and shutdown aren't duplicated
  across binaries.
- **No `envy`/`figment`.** Neither was available offline, so `runtime::config::Env` is a small
  typed loader that tests feed with a `HashMap`.
- **`installations::delete` keeps the row** and marks it suspended, because tips reference it.
  Only the repo list is removed.
- **Single-blob encryption format.** The PRD's separate `data_key_ciphertext` column is dropped
  (RFC 0001).
- **CORS behaviour.** With one allowed origin, tower-http always sends that origin. Browsers on any
  other origin see a mismatch and block, which the test asserts.

## Repository and config changes

- **`docker-compose.yml`:** the Postgres host port is now `${POSTGRES_PORT:-5432}`. This machine
  already had a Postgres on 5432, so local dev here uses 5435.
- **`.env.example`:**
  - New `APP_ENV`, `MASTER_KEY_PREVIOUS`, `WORKER_CONCURRENCY` and `POSTGRES_PORT`.
  - `EMAIL_FROM` is now quoted. Unquoted, dotenv failed to parse it.
  - `MASTER_KEY` is now needed by the api too.
- **`Makefile`:**
  - New `check-backend`, `sqlx-prepare` and `migrate-new` targets.
  - `openapi` is wired up.
  - `.env` is included so `DATABASE_URL` reaches `sqlx`.
  - `make help` is fixed.
- **Workspace deps added:** `hkdf`, `getrandom`, `base64`, `tokio-util`, `clap`, `tower` (dev).
  `aes-gcm` gained the `zeroize` feature. tower-http gained `timeout`, `request-id` and
  `sensitive-headers`.
- **API contract:** `/healthz` is now documented in OpenAPI (logged in
  `docs/api-contract-changes.md`). The frontend's `schema.d.ts` was regenerated, and
  `pnpm check` passes.

## Not verified here

- **`cargo deny`** is not installed locally. CI runs it via `cargo-deny-action`. The new crates are
  MIT/Apache-2.0, which `deny.toml` allows.
- **Coverage (`cargo llvm-cov`)** is not installed. That gate is M5.

## Code review fixes

A review of the branch found 10 issues. Each is fixed in its own commit, with a regression test
where one can be written:

| Issue | Fix |
| --- | --- |
| Jobs running longer than the lease could be reclaimed and run twice | The runner renews the lease every `lease / 3` (`jobs::heartbeat`). If the lease is lost anyway, the handler is aborted and nothing is recorded |
| Handlers kept running detached after a drain timeout | The handler task is owned by an abort-on-drop guard |
| A reused GitHub login could resolve to its previous owner | New migration `users_login_stale`. Upsert marks other holders of the login stale, and a partial unique index allows one current holder |
| Retry times mixed the app clock with Postgres `now()` | `jobs::retry`/`reschedule` take a delay and compute `run_at` in SQL. `JobOutcome::Reschedule` now carries a `Duration` |
| Rotating `MASTER_KEY` broke derived keys | `Keyring::verification_subkeys` also accepts the previous key's subkey; `subkey` is for creating values only |
| Single-writer guard only matched the literal `SET state` | It now parses `UPDATE tips … SET` assignments and `INSERT INTO tips (…)` columns, with its own unit tests |
| `make openapi` truncated the spec when the build failed | Writes to a temp file and moves it into place |
| 413/503 responses had no CORS headers and no JSON shape | CORS is outside the limit and timeout layers, and a response mapper normalises non-JSON errors |
| RNG failure produced predictable lease tokens | `Runner::new` returns an error, and slots don't claim without a fresh nonce |
| Each NOTIFY woke every idle slot | One `notify_one` per notification |

Two commits on the branch (`b2cdd78`, `7100531`) were not `rustfmt`-clean; `03a8953` fixes that.
Their tests and clippy were run individually when they were made.

## Known risks and follow-ups for M2

- `engine` crate: create it (ADR 0002) for event processing, tip creation and verification.
- Webhook endpoint: needs `GITHUB_WEBHOOK_SECRET` in `ApiConfig`, and probably a tighter body limit
  than the global 5 MiB.
- Job kinds are plain strings today. M2 should add typed payload structs per kind in `engine`.
